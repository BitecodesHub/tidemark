# Devlog 2: the kernel spike runs (2026-10-18)

The Phase 0 kernel spike now builds and runs. On a stock Fedora 45 Beta virtual
machine (kernel 7.2.0-61, aarch64, SELinux enforcing) on an Apple M1 Pro, all 12
scenarios passed in three consecutive, identical runs.

What this shows, on this kernel and architecture only:

- A session's label rises before `open()` returns, for a grandchild process.
- Labels rise for descriptors received over a Unix socket and for files that
  are only memory-mapped.
- Labels rise through an overlay mount, by directory rule and by the lower
  file's attribute.
- A capability-less session cannot rewrite its own label attribute.
- When the probe cannot read a label, it fails closed.

The first real build also exposed three kernel details that reading the
sources had missed, all now fixed: the generated kernel header needs a compiler
extension, a BPF helper no longer accepts stack memory, and Fedora's kernel
already marks one hook argument as possibly null.

The spike also confirmed three gaps it was designed to record. Reading a file
through a descriptor opened before the session started is not seen. A
namespace alias escapes directory rules. A hard link or a rename out of a
protected folder also escapes them. The first two have planned mitigations;
the third needs a design decision.
